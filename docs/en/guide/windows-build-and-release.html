Windows Build and Release

Build with MSVC, package the Qt runtime, and publish a ZIP

Windows Qt 6 ZIP GitHub Releases

The Windows ZIP contains the application (ShogiBoardQ.exe and shogiboardq-cli.exe), the runtime DLLs, the translations, six tsume shogi collection files, the Hayanagi executable with its opening book, and the root LICENSE. It does not contain README files. Hayanagi/source/ and an external licenses/ folder will not be included in future Windows releases either. The license display built into the application is used as it is.

Attach only the runnable ZIP to a release; do not attach the Qt sources or related documents separately. For how the license documents inside the application are prepared, see the policy on Qt documents and release attachments (Japanese).

2. Setting up the development environment

2.1 Installing Visual Studio

Install Visual Studio and select the following workload:

  • Desktop development with C++

This includes the MSVC compiler, CMake, and Ninja.

The Community Edition is free for individual and open-source development.

2.2 Installing Qt 6

Method A: Qt Online Installer (recommended)

Download the installer from the official Qt site and select the following components:

  • Qt 6.x > MSVC 2019/2022 64-bit
  • Qt 6.x > Qt Charts
  • Qt 6.x > Qt Multimedia
  • Developer and Designer Tools > CMake
  • Developer and Designer Tools > Ninja

After installing, set the Qt paths in environment variables:

# Add to the user environment variables (change the Qt installation path to match your environment)
# Example: C:\Qt\6.12.0\msvc2022_64
[Environment]::SetEnvironmentVariable("Qt6_DIR", "C:\Qt\6.12.0\msvc2022_64\lib\cmake\Qt6", "User")
[Environment]::SetEnvironmentVariable("PATH", "C:\Qt\6.12.0\msvc2022_64\bin;$env:PATH", "User")

Method B: aqtinstall (for CI and the command line)

pip install aqtinstall
aqt install-qt windows desktop 6.12.0 win64_msvc2022_64 -m qtcharts qtmultimedia

2.3 Installing Ninja (recommended)

Use the Ninja included with Visual Studio, or install it separately:

winget install Ninja-build.Ninja

2.4 Checking the installation

Check in Developer PowerShell for VS 2022 (started from the Start menu):

cmake --version       # 3.16 or later
cl                    # MSVC compiler
ninja --version       # Ninja
windeployqt --version # Qt deployment tool

3. Building

The Hayanagi engine for regular games is a submodule, so clone with --recurse-submodules (without it, CMake stops):

git clone --recurse-submodules https://github.com/hnakada123/ShogiBoardQ.git
cd ShogiBoardQ

If you cloned the repository before its history was rewritten on 2026-11-09, do not run git pull. It stops with an error or produces a large number of conflicts. Clone again into a different folder with the command above. Before deleting the old folder, move any unpushed commits and local settings. To see which history a clone has, run git log -1 --format=%h 2026.11.04. Output starting with 376e4362, or an error that 2026.11.04 cannot be found, means the old history, and output starting with aa9bcc4b means the new one. To keep your build folder, you can instead run git fetch origin --tags --force and then git reset --hard origin/main. This discards uncommitted changes and unpushed commits.

In an existing checkout, run git submodule update --init --recursive to fetch the recorded Hayanagi version.

Build script (recommended)

scripts/build-windows.ps1 runs everything from the Release build to creating the ZIP in one step.

Important: run it from Developer PowerShell for VS 2022 (the MSVC environment variables are required).

# Normal build + ZIP
.\scripts\build-windows.ps1

# Clean build, no ZIP
.\scripts\build-windows.ps1 -Clean -SkipZip

# Build into per-version directories (for a release)
.\scripts\build-windows.ps1 -BuildDir build\msvc-release-2026.10.07 `
    -DeployDir build\releases\2026.10.07-windows\deploy `
    -ZipPath build\releases\2026.10.07-windows\ShogiBoardQ-windows.zip
OptionDescription
-CleanDelete the build and deploy directories before building
-SkipZipSkip creating the ZIP (only the deploy folder is produced)
-BuildDirBuild directory (default: build)
-DeployDirDistribution directory (default: deploy)
-ZipPathZIP file to create (default: ShogiBoardQ-windows.zip)
-HelpShow help

The script performs the following steps automatically:

  1. Checks that the required tools exist (cmake, ninja, cl, windeployqt, and the location of the MSVC runtime DLLs)
  2. CMake configure + build (ShogiBoardQ, shogiboardq-cli, and Hayanagi)
  3. Checks the build outputs (.exe, .qm translation files, hayanagi.exe and its opening book, and one collection file per move count)
  4. Creates the deploy directory + places the collections, Hayanagi (including its opening book), and LICENSE + deploys the DLLs with windeployqt + adds qoffscreen.dll + copies the MSVC runtime DLLs + verifies the result
  5. Creates the ZIP file

If Qt is not on your PATH, specify its location before running the script (example: Qt 6.12.0):

$env:PATH = "C:\Qt\6.12.0\msvc2022_64\bin;C:\Qt\Tools\Ninja;$env:PATH"
$env:CMAKE_PREFIX_PATH = "C:\Qt\6.12.0\msvc2022_64"

If you get an execution policy error:

Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser

The rest of this guide describes how to run the individual commands by hand.

3.1 Release build

Run in Developer PowerShell for VS 2022:

cd C:\path\to\ShogiBoardQ

# Configure (Release build, Ninja)
cmake -B build -S . -G Ninja -DCMAKE_BUILD_TYPE=Release

# Build
ninja -C build

Without Ninja (using the Visual Studio generator):

# Configure
cmake -B build -S .

# Release build
cmake --build build --config Release

To run the tests:

cmake -B build -S . -G Ninja -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=ON
ninja -C build
ctest --test-dir build --output-on-failure

3.2 Checking the build outputs

# Check that the exe was generated
# With Ninja:
dir build\ShogiBoardQ.exe

# With the Visual Studio generator:
dir build\Release\ShogiBoardQ.exe

# Check the translation files
dir build\*.qm           # Ninja
dir build\Release\*.qm   # VS generator

3.3 Running the application

# Start the built application (in an environment where the Qt DLLs are on PATH)
.\build\ShogiBoardQ.exe

4. Creating the distribution package

Note: if you use scripts/build-windows.ps1, the steps in this section are performed automatically.

4.1 Creating the deploy directory

Copy the exe files, the translation files, the tsume shogi collections, Hayanagi with its opening book, and LICENSE to the distribution directory:

mkdir deploy, deploy\Hayanagi\book, deploy\data\tsumeshogi
copy build\ShogiBoardQ.exe deploy\
copy build\shogiboardq-cli.exe deploy\
copy build\*.qm deploy\
copy build\Hayanagi\hayanagi.exe deploy\Hayanagi\
copy build\Hayanagi\book\hayanagi_book.db deploy\Hayanagi\book\
copy data\tsumeshogi\tsume_*ply_*.txt deploy\data\tsumeshogi\
copy LICENSE deploy\

The tsume shogi collections are included as one file each for 3, 5, 7, 9, 11, and 13 moves to mate, six files in total (make sure no older version for the same move count remains in data/tsumeshogi/; the script stops if there is more than one). README files (in the root, Hayanagi/, and data/tsumeshogi/) are not included. Hayanagi's opening book hayanagi_book.db, which the build copies to build/Hayanagi/book/, goes to Hayanagi/book/. Hayanagi reads the book from book/ in its working directory, and ShogiBoardQ starts each engine with the engine's own directory as the working directory, so the book is used with the ZIP extracted as it is. Do not copy the whole source tree or build folder, and check before publishing that the ZIP contains neither Hayanagi/source/ nor licenses/. The build/licenses/ folder that a normal build generates is not copied into the Windows ZIP either.

4.2 Deploying the Qt DLLs with windeployqt

windeployqt --release --no-translations --no-system-d3d-compiler --no-opengl-sw --no-compiler-runtime deploy\ShogiBoardQ.exe deploy\shogiboardq-cli.exe

# shogiboardq-cli renders boards with the offscreen platform. windeployqt does not copy it, so add it
copy C:\Qt\6.12.0\msvc2022_64\plugins\platforms\qoffscreen.dll deploy\platforms\

What windeployqt does automatically:

  1. Copies the Qt DLLs the application depends on (Qt6Core, Qt6Gui, Qt6Widgets, Qt6Charts, Qt6Network, Qt6Multimedia, and so on)
  2. Copies the Qt plugins (platforms/qwindows.dll, imageformats/, and so on)
OptionDescription
--releaseDeploy the DLLs for a Release build
--no-translationsExclude Qt's translation files (the application's own .qm files were already copied by hand)
--no-system-d3d-compilerExclude d3dcompiler_47.dll (normally not needed)
--no-opengl-swExclude software OpenGL
--no-compiler-runtimeDo not bundle vc_redist.x64.exe (the runtime DLLs are copied directly in the next step)

4.2.1 Copying the MSVC runtime DLLs

So that the application starts even on a PC without the Visual C++ Redistributable, bundle the MSVC runtime DLLs (vcruntime140.dll, msvcp140.dll, and so on) in the same directory as the exe. In Developer PowerShell for VS, the VCToolsRedistDir environment variable points to where the runtime is located:

copy "$env:VCToolsRedistDir\x64\Microsoft.VC*.CRT\*.dll" deploy\

Hayanagi\hayanagi.exe looks for DLLs only in its own directory, so also place just the three it loads (vcruntime140.dll, vcruntime140_1.dll, and msvcp140.dll) in Hayanagi\:

foreach ($dll in "vcruntime140.dll", "vcruntime140_1.dll", "msvcp140.dll") {
    copy "$env:VCToolsRedistDir\x64\Microsoft.VC*.CRT\$dll" deploy\Hayanagi\
}

By default windeployqt bundles vc_redist.x64.exe (about 18 MB) instead of the DLLs, but the runtime is not installed unless the user runs it by hand, so the DLLs are bundled directly.

4.4 Testing

Start the application directly from the deploy folder to test it:

.\deploy\ShogiBoardQ.exe

# CLI (version and creating a board image)
.\deploy\shogiboardq-cli.exe version
.\deploy\shogiboardq-cli.exe render-board --sfen startpos --output board.png --overwrite

# Hayanagi (started in the Hayanagi folder, as ShogiBoardQ does; it should answer with
# id name Hayanagi … and info string book loaded)
cmd /c "cd deploy\Hayanagi && (echo usi& echo isready& echo quit) | .\hayanagi.exe"

Important: test in an environment where Qt's bin directory is not on PATH. If Qt is on PATH, the system's DLLs are used instead of those in the deploy folder, and missing files in the deployment go undetected.

4.5 Creating the ZIP file

Compress-Archive -Path deploy\* -DestinationPath ShogiBoardQ-windows.zip

5. Publishing on GitHub Releases

5.1 Creating the tag

Update the version only on the day of a release, to that date (Versioning and releases (Japanese)). Before building the packages, change APP_VERSION in CMakeLists.txt and commit it, build the packages from that commit, and then tag the same commit with the same version. Do not put a leading v on the tag.

git tag -a 2026.10.07 -m "ShogiBoardQ 2026.10.07"
git push origin main 2026.10.07

5.2 Creating the release with GitHub CLI

Use GitHub CLI (gh):

# Install
winget install GitHub.cli

# Log in (first time only)
gh auth login

Create the release and upload the asset:

gh release create 2026.10.07 `
  --title "ShogiBoardQ 2026.10.07" `
  --notes-file RELEASE_NOTES.md `
  ShogiBoardQ-windows.zip

To publish the macOS ZIP at the same time, add it as an asset:

gh release create 2026.10.07 `
  --title "ShogiBoardQ 2026.10.07" `
  --notes-file RELEASE_NOTES.md `
  ShogiBoardQ-windows.zip `
  ShogiBoardQ-macos.zip

Generating release notes automatically

If you do not prepare a release notes file, GitHub generates the notes:

gh release create 2026.10.07 `
  --title "ShogiBoardQ 2026.10.07" `
  --generate-notes `
  ShogiBoardQ-windows.zip

5.3 Creating the release from the web UI (alternative)

  1. GitHub repository → Releases → Draft a new release
  2. Choose a tag → enter a new tag (example: 2026.10.07) and create it
  3. Enter the Release title (example: ShogiBoardQ 2026.10.07)
  4. Write the release notes in Description
  5. Drag and drop ShogiBoardQ-windows.zip onto Attach binaries
  6. Click Publish release

6. Code signing (optional)

The application runs without a signature, but a SmartScreen warning appears the first time it is started.

6.1 Obtaining a code signing certificate

An EV (Extended Validation) code signing certificate is recommended for code signing. For individual developers, an OV (Organization Validation) certificate is also an option.

Main providers:

  • SignPath Foundation (free, for open-source projects)
  • DigiCert
  • Sectigo
  • GlobalSign

6.2 Signing with signtool

# Use signtool, included in the Windows SDK
signtool sign /fd SHA256 /tr http://timestamp.digicert.com /td SHA256 `
  /f "certificate.pfx" /p "password" `
  deploy\ShogiBoardQ.exe deploy\shogiboardq-cli.exe deploy\Hayanagi\hayanagi.exe

Sign before creating the ZIP. When using the script, build up to the deploy folder with -SkipZip, sign, and then create the ZIP (the steps in 4.5).

6.3 Distributing without a signature

Give users the following instructions:

  1. After downloading, right-click the ZIP → Properties → check “Unblock” → OK
  2. Extract it, then run ShogiBoardQ.exe
  3. If a SmartScreen warning appears, click “More info” → “Run anyway”

7. Troubleshooting

Qt is not found

CMake Error: Could not find a package configuration file provided by "Qt6"

Specify the Qt installation path explicitly:

cmake -B build -S . -G Ninja -DCMAKE_BUILD_TYPE=Release `
  -DCMAKE_PREFIX_PATH="C:\Qt\6.12.0\msvc2022_64"

cl.exe is not found

If you are not using Developer PowerShell for VS 2022:

Start Developer PowerShell for VS 2022 from the Start menu. Calling vcvarsall.bat from a regular PowerShell does not leave the environment variables it sets in PowerShell. To load the MSVC environment into the PowerShell you already have open, run the script included with Visual Studio:

# For Visual Studio 2022 Community
& "C:\Program Files\Microsoft Visual Studio\2022\Community\Common7\Tools\Launch-VsDevShell.ps1" -Arch amd64 -SkipAutomaticLocation

windeployqt is not found

# Check the Qt installation path and add it to PATH
$env:PATH = "C:\Qt\6.12.0\msvc2022_64\bin;$env:PATH"

# Check
windeployqt --version

The application does not start (DLL error)

Errors such as "Qt6Core.dll was not found"

  1. Run windeployqt again

  2. Check that all required DLLs exist in the deploy directory:

    dir deploy\Qt6Core.dll
dir deploy\Qt6Gui.dll
dir deploy\Qt6Widgets.dll
dir deploy\Qt6Charts.dll
dir deploy\Qt6Network.dll
dir deploy\platforms\qwindows.dll

  3. If the MSVC runtime is missing:

    • Copy the MSVC runtime DLLs into deploy again by following 4.2.1 (when they are bundled, the Visual C++ Redistributable does not need to be installed)

The Qt Charts DLLs are not deployed

If windeployqt cannot detect Qt Charts, copy the DLLs by hand:

copy "C:\Qt\6.12.0\msvc2022_64\bin\Qt6Charts.dll" deploy\
copy "C:\Qt\6.12.0\msvc2022_64\bin\Qt6OpenGL.dll" deploy\
copy "C:\Qt\6.12.0\msvc2022_64\bin\Qt6OpenGLWidgets.dll" deploy\

Translations are not loaded

Check that the .qm files exist in the same directory as the exe:

dir deploy\*.qm

If they do not, copy them by hand from the build directory:

copy build\ShogiBoardQ_ja_JP.qm deploy\
copy build\ShogiBoardQ_en.qm deploy\
copy build\ShogiBoardQ_zh_CN.qm deploy\
copy build\ShogiBoardQ_zh_TW.qm deploy\

Execution policy error (PowerShell scripts)

... cannot be loaded because running scripts is disabled on this system.
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser

SmartScreen warning (unsigned)

Instructions for users:

  1. Right-click the ZIP → Properties → check Unblock → OK
  2. Extract the ZIP before running the application
  3. “Windows protected your PC” → More info → Run anyway

As the number of downloads grows, SmartScreen's trust in the file increases and the warning appears less often.

Hayanagi Shogi Engine

Play, analyze, and practice tsume shogi against a defender

USI Support C++17 Adjustable Strength Mate Search ShogiBoardQ Submodule

About Hayanagi

A shogi engine written in C++17 and integrated with ShogiBoardQ

Hayanagi supports the USI protocol, which lets shogi GUIs exchange moves and search results with an engine. It is managed as a Git submodule of ShogiBoardQ. The same source builds both an executable for regular games and an embedded library for tsume shogi.

How to use itFeatures and setup
Register as a USI engineUse it for games, game analysis, position analysis, and mate search. Register the executable in Engine Settings.
Use the built-in tsume engineCheck puzzles for mate and generate defensive replies. It is embedded in ShogiBoardQ, so no additional engine registration is needed.

Source code and detailed specifications are available in the Hayanagi GitHub repository. This guide describes Hayanagi 1.4.0 from the included submodule.

Games and Adjustable Strength

Supports time controls, byoyomi, increments, and pondering during the opponent's turn. Limit search effort to adjust playing strength.

Position and Game Analysis

Reports evaluations, principal variations, search depth, and node counts. Compare several candidate moves with MultiPV.

Opening Books and Game Rules

Reads YaneuraOu DB2016 opening books and handles repetition, perpetual check, impasse, and entering-king rules.

Dedicated Mate Search

Searches for forced mate through continuous checks, including positions without the attacking king. The defender finds the longest resistance or an escape.

Use Hayanagi in ShogiBoardQ

Register the USI executable for regular games and analysis

1

Locate the Executable

In the Linux distribution ZIP, use Hayanagi/hayanagi inside the extracted folder. Building ShogiBoardQ from source produces build/Hayanagi/hayanagi. On Windows, the filename ends in .exe and may be placed in a configuration subfolder such as Release.

To build it yourself, see the build instructions below. On Linux and macOS, select a file with executable permission.

2

Register in Engine Settings

Open Settings → Engine Settings, click Add, and select the Hayanagi executable. Registration is complete when Hayanagi appears in the list. Use the Settings button to adjust thread count, playing strength, and other options.

See the engine registration guide for instructions with screenshots.

3

Select It for Games or Analysis

Select Hayanagi as a player in game setup for a human vs. engine or engine vs. engine game. You can also select it in Consideration Mode or Game Analysis.

To solve puzzles on the board, open Game → Tsume Shogi Play. The built-in Hayanagi is ready to use. See the Tsume Shogi Play guide for details.

Key Engine Settings

Adjust the registered USI engine to suit your needs

OptionDescription
ThreadsSearch thread count. Default: 1; range: 1–128. Choose a value that suits your CPU and other running tasks.
Hash / USI_HashMemory for storing positions during regular search, in MB. Both names control the same setting. Default: 16 MB.
MultiPVNumber of candidate lines to report. The engine supports 1–32. ShogiBoardQ's analysis panel uses its own line-count setting.
USI_PonderPonder during the opponent's turn. Disabled by default. Use the Pondering section in ShogiBoardQ's engine settings.
USI_LimitStrength
USI_Strength		Enable strength limiting and choose a value from -15 to 6 to cap search depth and nodes. Negative values represent approximate kyu ranks, positive values dan ranks, and 0 is treated as 1 kyu. Limiting is disabled by default.
USI_AnalyseModeDisables strength limits, immediate book moves, automatic resignation, and ponder requests for analysis. Unlimited thinking time must be requested separately.
USI_OwnBook
BookDir / BookFile		Control opening book use and its location. Enabled by default, looking for book/standard_book.db relative to the executable. Supply the book file separately.
EnteringKingRuleChoose entering-king rules, including the 24-point, 27-point, and try rules. Default: CSARule24.

Strength ranks are approximate and have not been calibrated through games. They are not guaranteed to match human ranks. Hayanagi is a minimal engine with a simple evaluation function considering material, piece activity, king safety, and related factors.

These options apply to the registered USI engine. For the built-in tsume solver, use the engine and time-limit controls in the puzzle list and play window.

Mate Search and Tsume Shogi

Distinguish mate, proven no-mate, and unresolved positions

UseBehavior
Mate SearchRequests a search from the registered Hayanagi using standard USI go mate. A mate result includes the full line with the defender's longest resistance.
Tsume Shogi PlayThe built-in Hayanagi checks puzzles and plays defensive replies to your checks. If you miss the mate, it shows an escape.
Tsume Shogi GenerationThe built-in Hayanagi screens candidate positions. You can also select the registered Hayanagi as the USI engine that verifies mates.

Standard USI go mate has a search limit of 63 plies. ShogiBoardQ's built-in initial-position check in Tsume Shogi Play is limited to 31 plies. Reaching a time or depth limit is treated separately from proving that no mate exists.

The depth-first search can take time on long puzzles, roughly 15 plies or more. For longer puzzles, register KomoringHeights and select it as the puzzle list's checking engine. Hayanagi still provides the defensive replies.

Build from Source

Build Hayanagi with ShogiBoardQ or on its own

Build with ShogiBoardQ

Run these commands from the ShogiBoardQ repository root. After fetching the submodule, the normal build produces both the application and Hayanagi.

git submodule update --init --recursive
cmake -B build -S . -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release

See Build & Installation for Qt and other prerequisites. With a typical Linux or macOS build, register build/Hayanagi/hayanagi as the engine.

Build Only Hayanagi

After fetching the submodule, run the following from the ShogiBoardQ repository root. Hayanagi itself does not depend on Qt; it requires CMake 3.16 or later and a C++17 compiler.

cmake -S Hayanagi -B build-hayanagi -DCMAKE_BUILD_TYPE=Release
cmake --build build-hayanagi --config Release
./build-hayanagi/hayanagi --version

The last command is for Linux and macOS. On Windows, run hayanagi.exe from its output directory. For USI commands, search internals, tests, and release history, see the Hayanagi README.

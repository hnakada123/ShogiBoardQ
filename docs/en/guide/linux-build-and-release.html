Requirements and setup

Install a C++17 compiler, CMake 3.16 or later, Git, and a Qt 6.7 or later desktop SDK. ShogiBoardQ needs Qt Widgets, Charts, Network, Concurrent, Multimedia, Sql, and LinguistTools. Install the Qt SVG and SQLite plugins for packaging as well. Ninja is recommended; Python 3 is needed by the packaging scripts.

For example, install the build tools on Ubuntu or Debian:

sudo apt update
sudo apt install build-essential cmake ninja-build git curl file python3

Use the Qt Online Installer to install a Linux desktop kit, including Qt Charts, Qt Multimedia, and the developer tools. Distribution packages can also be used if they provide all required modules at version 6.7 or later. The Qt 6.7.3 official SDK is used in the examples below; adjust paths to your installation.

export CMAKE_PREFIX_PATH="$HOME/Qt/6.7.3/gcc_64"
export PATH="$HOME/Qt/6.7.3/gcc_64/bin:$PATH"

AppImage tools may require FUSE. The packaging script downloads linuxdeploy and appimagetool, so packaging also requires network access. Build and test on the oldest distribution you intend to support: an AppImage still depends on the host's compatible system libraries, including glibc.

Get the source and build

Clone the repository with its Hayanagi submodule. An ordinary clone without submodules is incomplete.

git clone --recurse-submodules https://github.com/hnakada123/ShogiBoardQ.git
cd ShogiBoardQ

For an existing checkout, initialize the recorded submodule version with git submodule update --init --recursive.

cmake -B build -S . -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel
./build/ShogiBoardQ

For a development build through the helper script, use ./scripts/build-linux.sh --skip-appimage. This stops after building and does not prepare an AppDir or a distributable package.

To enable and run the test suite:

cmake -B build -S . -DBUILD_TESTING=ON
cmake --build build --parallel
ctest --test-dir build --output-on-failure

Prepare Qt notices and corresponding sources

A normal local CMake build does not download Qt sources. The distribution scripts additionally require prepared license documents for the exact Qt build they deploy. They include those documents and source information in the package and stop if validation fails.

For the unmodified official Qt 6.7.3 SDK, run the following from the repository root. These commands use the version and SHA-256 recorded in the release workflow. For a different Qt build, use its matching full source archive, checksum, and provenance instead.

python3 scripts/qt_licenses.py fetch --version 6.7.3 --sha256 a3f1d257cbb14c6536585ffccf7c203ce7017418e1a0c2ed7c316c20c729c801 --output build/qt-sources
python3 scripts/qt_licenses.py prepare --version 6.7.3 --archive build/qt-sources/qt-everywhere-src-6.7.3.tar.xz --sha256 a3f1d257cbb14c6536585ffccf7c203ce7017418e1a0c2ed7c316c20c729c801 --source-url https://download.qt.io/archive/qt/6.7/6.7.3/single/qt-everywhere-src-6.7.3.tar.xz --provenance "Official Qt 6.7.3 SDK, unmodified; build scripts in source archive" --output build/qt-licenses

The source archive is a large separate download, roughly 900 MB. The preparation command does not overwrite an existing output directory. A clean build deletes build; if using the script's clean option, prepare the sources and notices outside that directory and set SHOGIBOARDQ_QT_LICENSE_DIR to the notices directory.

Publish the matching application source, including Hayanagi, and Qt sources alongside the binaries. GitHub's automatically generated source ZIP does not include submodule contents. For patched Qt builds, preserve the patches and build instructions too. The repository's Qt distribution notes (Japanese) describe the packaging policy and source manifests.

Create a AppImage package

After preparing the matching Qt notices and source archive, run:

./scripts/build-linux.sh

The script builds the application, assembles build/AppDir, deploys Qt and the required plugins, copies translations and license documents, and creates ShogiBoardQ-linux-x86_64.AppImage in the repository root. The QSQLITE plugin is checked so that tsume puzzle history works in the distributed application.

chmod +x ShogiBoardQ-linux-x86_64.AppImage
./ShogiBoardQ-linux-x86_64.AppImage

Test the AppImage on a separate machine or environment without the Qt development SDK. Check English/Japanese switching, SVG pieces, sound, and saving tsume puzzle progress. Use --help to see the script's options.

Publish on GitHub Releases

The repository includes a release workflow that builds all three platforms, prepares corresponding sources and license documents, and uploads binaries, source archives, checksums, and an SBOM to the same GitHub Release.

For maintainers with push access, pushing a release tag beginning with v triggers this workflow. It can also be run from the Actions tab with an existing release tag. Choose the intended release commit and tag, then review the workflow results and attached files.

For a manual release, open the repository's Releases page and create a release for the intended tag. Attach the tested AppImage, the application source archive containing Hayanagi, the matching Qt source archive, and source/build information and checksums. Retain these source downloads while the binaries remain available. The application package must contain its prepared license documents as well.

Troubleshooting

  • Qt6Config.cmake or a Qt module is missing: confirm the SDK version and required modules, then set CMAKE_PREFIX_PATH to the kit directory. Use a fresh build directory after switching Qt kits or CMake generators.
  • Hayanagi source files are missing: run git submodule update --init --recursive from the repository root.
  • FUSE is unavailable: extract the completed image with ./ShogiBoardQ-linux-x86_64.AppImage --appimage-extract, then run ./squashfs-root/AppRun.
  • The xcb platform plugin cannot load: inspect the reported missing system libraries. For a Wayland-specific issue, try QT_QPA_PLATFORM=xcb ./ShogiBoardQ-linux-x86_64.AppImage in an environment with X11 support.
  • A newer glibc is required: rebuild on a distribution compatible with the target machine.
  • Translations or puzzle history do not work: check the packaged translation files and usr/plugins/sqldrivers/libqsqlite.so in the AppDir.
  • Qt notice validation fails: prepare notices for the exact Qt build being deployed and retain the corresponding sources. Do not ignore a failed packaging step.

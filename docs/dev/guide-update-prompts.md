# ガイド更新・新機能作成の依頼テンプレート（/clear 後に使う）

会話が長くなったら `/clear` してから、下のテンプレートを貼り付けて依頼します。
過去の作業の要点はメモリ（`~/.claude/projects/-home-nakada-GitHub-ShogiBoardQ/memory/`）に、
撮影・ページ生成の補助スクリプトはリポジトリの [scripts/docs/](../../scripts/docs/README.md) にあるので、
`/clear` しても同じ手順で続けられます。`<…>` の部分を書き換えて使ってください。

## 共通の条件（どのテンプレートにも付ける）

```text
【共通の条件】
- 返答・作業報告・コミットメッセージは日本語でお願いします。
- 作業の前に scripts/docs/README.md と、メモリの docs-screenshot-workflow・translation-baseline-workflow・
  zh-tw-terminology を読んでください。撮影とページ生成には scripts/docs/ のスクリプトを使ってください。
- スクリーンショットは日本語・英語・中国語（簡体字・繁体字）の4言語すべてで撮ってください。
  各言語の画面で撮り、docs/images/<ページ>/（日本語）と docs/images/{en,zh-cn,zh-tw}/<ページ>/ に置きます。
  普段の設定に書き込まないよう、撮影は scripts/docs/launch.sh（ウィンドウ枠が要るときは kwin_capture.sh）で行ってください。
- ページは日本語・英語・簡体字・繁体字の4言語で作り、4言語の切り替えメニュー・hreflang・サイトマップ・
  ホームページ（scripts/docs/gen_home.py）のリンクも更新してください。
- 説明は推測で書かず、コードと実際の画面で確かめてください。画面の項目名は翻訳ファイルの訳と一致させてください。
- 動作確認中に不具合を見つけたら、逐次修正も実施してください。修正にはテストを付け、修正を外すと失敗することも確かめてください。
- tr() の文字列を変えたら、4言語の翻訳を入れて未翻訳0を保ってください。
- 確認: ctest 全体、GUI 監査（python3 tests/gui/prepare.py の後に run.py）、ページの表示（headless chromium）とリンク切れ。
- コミットとプッシュは、私が依頼するまでしないでください。
```


## 依頼後のやり取りの例

- 「コミットとプッシュをお願いします。」— 変更を内容ごとのコミットに分けてプッシュします。件名の後に空行を入れ、
  プッシュ前に件名が1行か確認します（main は強制プッシュできない保護ブランチです）。
- 「今回の作業以外で気づいた点を調べてください」— 作業中に気づいた不具合の候補を調べて報告・修正します。

# 版番号とリリースの運用

ShogiBoardQ の版番号は、リリースした日の日付にする（CalVer）。版番号はリリースする日にだけ上げ、版番号・タグ・Release 名を一致させる。2026-10-07 にこの運用に決めた。

## 形式

- `YYYY.MM.DD`（例: `2026.10.07`）。月と日は2桁で書く。
- 同じ日に2回目以降のリリースをするときは、4つ目の番号を付ける（`2026.10.07.1`、`2026.10.07.2`）。
  - CMake の `project(VERSION)` は4つまで使える。macOS のバンドルの版は Apple の規則では数字3つまでとされているが、App Store では配布していないので現状は支障がない。
- 版番号は `CMakeLists.txt` の `APP_VERSION` だけで決める。アプリと `shogiboardq-cli` の版、自動化 API・MCP の `version`、macOS のバンドルの版、「バージョン情報」の表示、詰将棋の問題集に記録する版は、すべてここから取る。

## 上げるとき

- リリースする日にだけ上げる。リリースしない変更では上げない。
- リリースとリリースの間のビルドは、前に上げた版番号のままになる。開発中のビルドかどうかは、「バージョン情報」のビルド日時で見分ける。

## リリースの手順

1. リリースに含める変更をすべてコミットし、テストを通す（`ctest`）。
2. `CMakeLists.txt` の `APP_VERSION` をその日の日付に変え、それだけをコミットする。

   ```bash
   git commit -m "バージョンを2026.10.07に更新する" CMakeLists.txt
   ```

3. そのコミットから各 OS の配布物を作る。手順は [Linux](linux-build-and-release.md)・[Windows](windows-build-and-release.md)・[macOS](macos-build-and-release.md) を参照。「バージョン情報」に新しい版番号が出ることを確かめる。
4. 同じコミットに注釈付きタグを付けて push する。タグには `v` を付けない。

   ```bash
   git tag -a 2026.10.07 -m "ShogiBoardQ 2026.10.07"
   git push origin main 2026.10.07
   ```

5. Release を作る。名前は `ShogiBoardQ 2026.10.07` にする。添付するファイルは各 OS の手順書に従う。ほかの OS の配布物を後から加えるときは `gh release upload` を使う。

   ```bash
   gh release create 2026.10.07 --title "ShogiBoardQ 2026.10.07" \
     --notes-file RELEASE_NOTES.md ShogiBoardQ-linux.zip
   ```

## リリース後に不具合が見つかったら

公開した配布物を、同じ版番号のまま作り直して差し替えない。同じ版番号で中身が違う配布物ができてしまう。修正をコミットし、新しい版番号でリリースする（同じ日なら `2026.10.07.1`）。

## 一部の OS だけに関わる修正のとき

Windows だけ、macOS だけなど、一部の OS だけに関わる修正でも、版番号を上げたら全 OS の配布物を新しい版番号で作り直し、同じ Release に添付する。

- 版番号はアプリに埋め込まれる（「バージョン情報」など）。作り直さない OS は、表示される版番号と Release 名が合わなくなる。
- 前の Release の配布物を新しい Release に添付し直さない。アプリの表示と Release 名がずれる。新しい Release から一部の OS を抜くこともしない。利用者は最新の Release を開くので、その OS の配布物が見つからなくなる。
- 影響のない OS は、リリースノートに「版番号の更新のみ（前の版から変更なし）」と書く。その OS の利用者が更新を急がなくて済む。
- Linux の作り直しは `./scripts/build-linux-container.sh` を1回実行するだけで、2回目以降は差分ビルドなので数分で終わる。確認は、起動と「バージョン情報」の版番号・ビルド日時を見る。

## タグと release.yml

- タグは、既存のタグ（`2026.02.22` 以降）と同じく `v` を付けない。
- `.github/workflows/release.yml` は `v` で始まるタグの push でしか自動では起動しない。日付のタグを push しても動かない。現在は、配布物を各 OS の手順で作って手動で添付している。

## 以前の運用

2026-10-07 より前は、リリースしない変更でも版番号を日付に上げていた。そのため、タグも Release もない版番号がある（2026.09.09・09.14・09.15・09.25・09.29・10.04・10.06 など）。Release がある版は `gh release list` で確かめる。

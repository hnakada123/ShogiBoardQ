# ウォレットを導入した場合の利用者の負担

作成日: 2026-11-11

状態: 判断の記録。[P2P対局の実装仕様](p2p-game-spec.md)は、第3版でブロックチェーンへの記録と外部ウォレットをやめた。本書は、その理由のうち利用者にかかる負担をまとめる。

対象: 第2版の構成（コミット `46e40330` の `docs/dev/p2p-blockchain-game-spec.md`）。本文の「第2版」はこの版を、「第3版」は現行の構成を指す。

根拠: 第2版の設計と、公開ブロックチェーンの一般的な性質に基づく。第2版は実装していないので、実際に測った数字はない。特定のチェーン、ウォレット、取引所の料金や条件は調べていない。

## 1. 要点

第2版は、将棋を指したいだけの利用者に次の3つを求めていた。

- 対局の前に、外部のウォレットを用意する。
- 対局のたびに、自分であることを示すためにウォレットで署名する（1局に2回）。
- 結果を公開の記録に残すには、暗号資産で手数料を払う。

どれも将棋を指すことには要らない作業である。対局は2人でするので、相手も同じ準備を済ませていなければ始まらない。

第3版はこの3つをなくした。身元はアプリが作るプレイヤー鍵にし、記録は双方の手元に残す証跡ファイルにした。代わりに公開の台帳がなくなった（6章）。

## 2. 第2版が利用者に求めていた操作

| 場面 | 利用者の操作 | 第2版の節 |
|---|---|---|
| 準備 | 外部ブラウザにウォレット拡張を入れ、アドレスを作る。対局には資産を持たない専用のアドレスを使う | 9.3・10.2 |
| ウォレットの接続 | アプリが開くブラウザのページでウォレットをつなぎ、取得されたアドレス（全桁）が自分のものか確かめる | 10.2・13 |
| 対局の開始 | 開始条件にウォレットで署名する。ウォレットに出る項目と値を、アプリの確認画面と見比べる | 5.3・10.2 |
| 終局 | 最終結果にウォレットで署名する | 5.4・10.2 |
| 公開の記録 | 記録先・見積り・上限を確かめ、ウォレットでトランザクションの送信を承認する。手数料は送信した側が払う | 10.3・10.4 |
| 記録の確認 | チェーンへの取り込みと最終確定を待つ。失敗、期限切れ、取り込みの巻き戻しに対処する | 10.3 |

第2版は、1人あたり開始時と終局時の2回の署名を必要とし、公開の記録を送る側はさらに送信の承認を必要とした（10.2節）。

## 3. 負担の内訳

### 3.1 始める前の準備

- **ウォレットを入れる。** 対応するブラウザとウォレット拡張が要る。将棋のアプリとは別のソフトを選び、入れ、更新し続けることになる。
- **復元用の語句を自分で保管する。** ウォレットを作ると、鍵を復元するための語句（シードフレーズ）を紙などに控えるよう求められる。失うとそのアドレスを二度と使えず、他人に知られるとそのアドレスの資産を持ち出される。パスワードのような再発行の窓口はない。
- **対局専用のアドレスを作る。** 資産を持つアドレスを対局に使うと、資産の持ち主と接続元の IP が相手から結び付く。第2版は専用のアドレスを使うよう案内することにしていた。利用者は、アドレスを使い分けるという考え方から覚える必要がある。
- **ウォレットのチェーンを合わせる。** ウォレットが別のチェーンを向いていると署名できない。第2版は、安全のためにチェーンの切り替えを自動で要求せず、利用者に案内するだけにしていた。
- **暗号資産を手に入れる。** 公開の記録を送る側は、そのチェーンの通貨を持っていなければならない（3.3節）。

### 3.2 対局のたびの操作

- **署名が2回、送信が1回。** 開始と終局のたびに、アプリからブラウザへ、ブラウザからウォレットへ移って承認し、アプリへ戻る。ウォレットがロックされていれば、そのパスワードも入れる。
- **中身を見比べる。** 署名の画面には、記録先の名前、チェーンの番号、コントラクトのアドレス、合意の各項目が英数字で並ぶ。第2版は、利用者がこれをアプリの表示と見比べることを安全の前提にしていた。見比べずに承認する利用者は、偽の要求にも承認する（3.4節）。
- **待ち時間が延びる。** 第2版では、開始署名の期限は条件の合意から3分で、署名待ちは最大10分まで延ばせた。相手がウォレットの操作に手間取る間、募集は止まり、自分は待つ。第3版は、条件を確かめて開始を押すだけになり、仮予約の60秒で足りる。
- **つまずく場所が増える。** 署名の拒否、ウォレットのアカウントの切り替え、チェーンの違い、ブラウザが開かない、ウォレット拡張がページを認識しない、といった失敗が加わる。どれも将棋とは関係がなく、利用者が原因を切り分けにくい。

### 3.3 手数料

- **暗号資産でしか払えない。** チェーンへの書き込みの手数料（ガス代）は、そのチェーンの通貨で払う。円やクレジットカードで直接は払えない。
- **入手に手間がかかる。** 暗号資産を買うには、取引所に口座を作り、本人確認を済ませ、購入し、自分のウォレットへ送る。手数料が少額でも、この手間は変わらない。取引所の最小の購入額や出金の手数料が、1局の手数料より大きいこともありうる。
- **金額が決まらない。** 手数料はチェーンと混雑で変わり、通貨の価格も変わる。第2版は固定の金額を仕様に置けず、送信の直前に見積りを出すことにしていた。利用者は、いくらかかるかを対局の前に知ることができない。
- **どちらが払うかを決める必要がある。** 払うのは送信した側である。双方が同時に送ると、記録は1つでも手数料は二重にかかりうる（第2版10.4節）。
- **失敗しても戻らない。** チェーンに取り込まれたうえで失敗したトランザクションにも手数料がかかる。
- **期限がある。** 第2版では、開始の期限から30日を過ぎると登録できない（5.3節）。暗号資産の用意が間に合わなければ、その対局は公開の記録に残らない。
- **会計の手間が生じる場合がある。** 国や地域によっては、少額の手数料の支払いも、暗号資産の損益の計算の対象になる。扱いは居住地の制度による。

署名そのものに手数料はかからない。公開の記録を一切送らないなら、暗号資産は要らない。ただしその場合、ウォレットを使う理由であった公開の記録も残らない。

### 3.4 利用者が負う危険

- **ウォレットの鍵は資産の鍵でもある。** 将棋の対局のために承認の操作を繰り返すうちに、資産を動かす要求を承認してしまうおそれがある。第2版は「ShogiBoardQ はトークンの承認、送金、シードフレーズの入力を求めない」と、接続時と署名の前に表示することにしていた。そう断らなければならない仕組みである。
- **偽物に狙われる。** ウォレットをつなぐアプリには、偽の配布物や偽のページで署名を求める手口が成り立つ。利用者は、要求が本物かどうかを毎回自分で判断することになる。
- **最後の防御が利用者の目になる。** 第2版は、アプリやその補助プロセスが侵害された場合に残る防御を、外部ウォレットの確認画面だけと見積もっていた（1.2節・5.1節）。
- **なくしたとき、漏れたときの損が大きい。** 第3版のプレイヤー鍵は、漏れてもなりすましで対局されるだけで、作り直せば済む。金銭の被害にはならない。

### 3.5 公開される情報

- **アドレスと対局の履歴が公開され、消せない。** だれと、いつごろ、どんな結果だったかが、チェーンに残り続ける（第2版9.3節）。
- **アドレスの残高と取引の履歴は、だれでも見られる。** 対局に使ったアドレスに資産があれば、相手にも第三者にも見える。
- **相手は IP とアドレスの両方を知る。** 資産を持つアドレスを使うと、資産の持ち主と接続元が結び付く。
- **チェーンへの問い合わせ先に見える。** 記録を調べるたびに、接続元の IP と、調べた対局・アドレスが、問い合わせ先の運営者に見える（第2版10.1節）。

第3版でも、相手にはプレイヤーID と IP が伝わる。違いは、記録が当事者の手元だけにあり、資産と結び付かないことである。

### 3.6 相手にも同じ準備が要る

対局には双方の署名が要る。自分が準備を済ませても、相手がウォレットを持っていなければ始まらない。友人を招待するには、友人にも 3.1節の準備を頼むことになる。公開の募集では、準備を済ませた人どうしでしか対局が成立せず、相手の数が減る。利用者の少ない実験版では、これが最も重い。

## 4. 負担が大きい利用者

| 利用者 | 困ること |
|---|---|
| 暗号資産を使ったことがない人 | 3.1節の準備のすべてが初めての作業になる。本アプリの利用者の多くはここに入ると見ている（確かめた数字はない） |
| 未成年 | 取引所の多くは口座の開設に年齢の条件を設けている。手数料を自分で用意できない |
| 暗号資産の売買が制限されている国・地域の人 | 手数料を用意する正規の手段がない |
| 学校や職場など、管理された PC を使う人 | ブラウザの拡張を入れられない |
| PC の操作に慣れていない人 | 英数字の見比べ、復元用の語句の保管、ブラウザとアプリの行き来でつまずく |
| すでに暗号資産を持っている人 | 資産のあるアドレスを対局に使ってしまうと、残高と IP が相手に伝わる。承認の操作を誤ったときの損も大きい |
| 招待された側 | 自分から望んだわけではない準備を、対局のために求められる |

## 5. 第2版と第3版の比較

| 項目 | 第2版（ウォレットあり） | 第3版（現行） |
|---|---|---|
| 始める前 | ウォレット拡張、アドレス、復元用の語句の保管 | なし。初回にアプリが鍵を作る |
| 開始まで | ブラウザとウォレットで署名。期限は3分、最大10分 | 条件を確かめて開始を押す |
| 終局後 | ウォレットで署名。公開の記録は送信の承認と手数料 | 操作なし。アプリが署名し、証跡を保存する |
| 費用 | 記録を送る側に暗号資産の手数料 | なし |
| 鍵をなくしたとき | そのアドレスを二度と使えない | 作り直す。相手からは別人に見える |
| 鍵が漏れたとき | なりすまし。資産があれば持ち出される | なりすまし。金銭の被害はない |
| 残る記録 | アドレスと結果がチェーンに残り、消せない | 当事者の手元のファイルだけ |
| 追加のプロセス | 通信、チェーン読み取り、ウォレット連携の3つ | 通信の1つ |

## 6. やめたことで失ったもの

負担だけを数えると判断が偏るので、失ったものも記す。

- **公開の台帳。** 第2版では、記録があること・ないことを第三者が確かめられた。第3版では、当事者がファイルを渡さない限り、第三者は記録を知らない。
- **矛盾する結果の防止。** 第2版のコントラクトは、同じ対局に異なる結果を登録させなかった。第3版では、双方が示し合わせれば矛盾する2つの記録を作れる。
- **時刻の手がかり。** チェーンに取り込まれた時刻より前に署名されたことが分かった。第3版の記録は、署名した時刻を証明しない。
- **保管を当事者に頼らないこと。** 結果のハッシュはチェーンに残った。第3版では、証跡ファイルを失えば復元できない。

一方、ウォレットを使っても得られなかったものがある。第2版でも、棋譜が規則に合うこと、人間が指したこと、時計が正しいことは、チェーンでは確かめなかった。負けた側が署名を拒めば記録が成立しない点も同じである。利用者の負担に見合うほど、保証が増えるわけではなかった。

## 7. 再び検討するときの条件

実装仕様は、ブロックチェーンへの記録を再検討する条件を「対局の開始条件にせず、利用者に費用を負わせない方法があるとき」とし、別仕様の任意機能として扱うと定めている（2.3節）。考えられる方法と、それぞれに残る問題は次のとおり。どれも採ると決めたものではない。

| 方法 | 減る負担 | 残る問題 |
|---|---|---|
| 対局はウォレットなしで行い、望む人だけが後から証跡のハッシュを記録する | 対局にウォレットも手数料も要らない。相手の協力も要らない | 記録する人の準備と手数料はそのまま残る。チェーンは署名を検証せず、検証は証跡ファイルで行う |
| 手数料を第三者が肩代わりする | 利用者は暗号資産を持たなくてよい | 肩代わりする運営者と費用が要り、乱用への対策も要る。専用のサーバを置かない方針と合わない。署名のためのウォレットは残る |
| 試験用のチェーンだけを使う | 価値のある暗号資産が要らない | 試験用の通貨の入手にも手間がかかる。試験用のチェーンは作り直しや終了があり、記録が残る保証がない。ウォレットは残る |
| アプリの中に鍵を持つ | 外部のウォレットの操作がなくなる | 手数料を払うなら、アプリが資産を動かせる鍵を持つことになり、守るものが増える。手数料を払わないなら、第3版のプレイヤー鍵と同じである |

# 対局情報ウィンドウのMCP検証（2026-09-27）

対局情報の表示、内容編集、更新、行追加、Undo/Redo、クリップボード、文字サイズ、
棋譜保存、未保存確認、終局時の更新、浮動ドックを実アプリで検証した。
PythonのMCP SDKからstdioサーバーを起動し、各テスト専用の設定・ソケット・保存先を使用した。

## 不具合と修正

| 条件 | 問題と修正 |
|---|---|
| 編集して「対局情報更新」 | 更新シグナルの接続がなく、盤面の対局者名や棋譜の未保存状態に反映されなかった。名前表示の更新と未保存化を接続 |
| 更新前の編集を残して別棋譜・新規棋譜へ移る | 未保存判定が棋譜モデルのみで、対局情報を無警告で破棄できた。入力中のセルも含めて確認する |
| 複数セルの編集、行追加後のUndo/Redo | Undoが全項目を戻し、Redoが機能しなかった。セル・行単位の履歴を保持し、追加行のキー編集可否も復元 |
| 初期化順序によって、読込後にUndo | プレイヤー情報コントローラに対局情報コントローラが未設定となり、読込前のスナップショットが残った。依存先を先に確保する |
| Enterを押す前に更新・保存 | QtのEnter処理による確定が次のイベント処理まで遅延し、保存内容から入力が漏れた。delegateの確定・終了シグナルを同期的に処理する |
| 対局者名の入力中に投了・自動保存 | 終局通知にフォーカスが移った後の入力欄を回収できず、終了日時の更新時に入力を失った。残っている入力欄も確定し、変更する項目だけを更新する |
| 対局情報を編集して棋譜保存 | 保存後も「修正中」が残った。成功時だけ編集を適用して未保存状態を解除し、失敗・中止時は保持する |
| Ctrl+Z/Y/X/C/V、文字列の一部を選択してツールバー操作 | テーブルにショートカットがなく、切り取り・コピー・貼り付けはセル全体を対象としていた。ペイン内のショートカットと入力欄の選択範囲に対応 |
| SFENへ変更、または対局者名・終了日時の自動更新後にUndo | 編集履歴と基準データの同期がなかった。別棋譜・局面の読込では履歴を初期化し、同一対局の自動更新では他の編集を保持する |
| 名前付き棋譜の後にSFENを読み込む | テーブルが空になっても盤面の名前が残っていた。ヘッダがない局面への変更時に名前も消去する。ラベル全文のMCP対応により既存回帰テストで検出 |

## MCPの追加機能

- `edit_table_cell`: 0始まりの行・列を指定し、通常のセル入力欄から編集する。
  `commit=false` で未確定の状態を再現できる。読み取り専用、非表示、無効、モーダル背後の操作は拒否する。
  ダイアログを閉じた直後など、ウィンドウが非アクティブでも生成済みの入力欄を見つけて入力する。
- 対局情報テーブル・各ボタン・編集状態ラベルと、盤面の対局者名にobjectNameを設定。
- 省略表示ラベルの全文を汎用プロパティ経由で取得できるようにし、画面の名前の反映も検証可能にした。

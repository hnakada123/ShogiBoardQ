# 新しい駒書体を依頼するためのプロンプト

ShogiBoardQで使う駒の書体・字形を新たに作るときの依頼文です。
ここでの成果物は、文字をパス化したSVG駒画像と比較用HTMLです。
2026-10-04に採用した明朝体アルファベット駒の仕様を引き継いでいます。

## `/clear`後の使い方

次の依頼文を貼り付け、希望する書体の部分を書き換えてください。このファイルを読むだけで、過去の会話なしに作業を再開できます。

```text
/home/nakada/GitHub/ShogiBoardQ/docs/dev/piece-font-request-prompts.md を読み、
「HTMLサンプルを作る依頼」の内容で、新しい駒書体のサンプルを作成してください。
希望する書体：和風の明朝体を基調に、既存の端正・凛・墨とは違う印象の3案。
```

このMarkdownはGit管理対象です。比較用HTMLを置く `design/` は `.gitignore` の対象なので、別の環境にチェックアウトした場合には存在しないことがあります。その場合は、リポジトリ内のSVGと生成スクリプトを参照してHTMLを作成してください。

## HTMLサンプルを作る依頼

以下は単独で貼り付けても使えるプロンプトです。「希望する書体」と「保存先」を必要に応じて変更してください。

```text
ShogiBoardQ向けに、新しいアルファベット書体の駒を3案作成し、比較用HTMLで見せてください。

作業場所：/home/nakada/GitHub/ShogiBoardQ
希望する書体：和風の明朝体を基調に、既存の端正・凛・墨とは違う印象の3案。
保存先：/home/nakada/GitHub/ShogiBoardQ/design/piece-font-new/
今回はHTMLサンプルとSVGの作成までをお願いします。

最初にAGENTS.mdと以下のファイルを読み、現在の実装を確認してください。
- resources/images/pieces/README.md
- scripts/generate_alphabet_pieces.py
- resources/shogiboardq.qrc
- resources/images/pieces/alphabet_sei_wood/ などの既存アルファベット駒
- design/alphabet-shogi/index.html（存在する場合）

文字と成駒：
- 王・玉=K、飛=R、角=B、金=G、銀=S、桂=N、香=L、歩=P。
- 通常の文字は黒 #111111、成駒は赤 #b3262e。
- 成駒でも文字は変えず、色で区別してください。
- と金=P、成香=L、成桂=N、成銀=S、馬=B、龍=R。
- 王・玉と金に成駒はありません。
- 駒面には一文字だけを置き、英単語・下線・プラス記号は付けないでください。

駒の形と文字の配置：
- 現在の標準駒と同じ五角形、縁の太さ、種類別のサイズ、先後の向きを使ってください。
- 標準駒の実体はshogiboardq.qrcの pieces/Sente_ou45.svg などのエイリアスから解決してください。
  特定のstandardディレクトリの存在を仮定しないでください。
- 全種類を同じ大きさにせず、文字も各駒の五角形の縮尺に比例させてください。
- 基準は、駒の縮尺を適用する前の45×45座標で、実際の字形の高さ22.0、
  五角形の下辺から字形下端までの余白6.5、左右中央から右への移動0.3です。
- 高さはフォントのポイント数や行ボックスではなく、字形パスの実際の上下端で合わせてください。
- この高さ・下余白・右寄せ量に、各駒の標準縮尺を一緒に適用してください。
- 同じ縮尺の駒同士では字形の高さと下余白を揃え、種類別の縮尺による大小は保ってください。
- RやNなどの上部が斜辺に接触しないようにしてください。
  字形の外接矩形と斜辺との横方向の余白は、基準座標で1.8＋縁幅の半分を目安にします。
- 左右非対称な文字の見た目も確認し、太さや字幅の違いが分かる3案にしてください。

配色：各案に木肌・白・墨を用意してください。
- 木肌：駒面 #f7e9c9、縁 #9b825c、盤・駒台 #dfc69a、罫線 #a28a60、背景 #e9dec4。
- 白：駒面 #fffef9、縁 #a9aaa0、盤・駒台 #dfe5dc、罫線 #a5afa0、背景 #e9ede7。
- 墨：駒面 #f4eada、縁 #b5a58b、盤・駒台 #384841、罫線 #809186、背景 #43504b。
- 墨の配色でも駒面は明るく、通常の文字は黒、成駒は赤のままにしてください。

HTMLとSVG：
- 案と配色を切り替え、通常駒・成駒の一覧、9×9の初期配置、成駒・持駒の見本、
  盤面反転、現在の標準駒とのサイズ比較を確認できるようにしてください。
- 拡大表示だけでなく、実際の盤上に近い小さな表示でも読みやすさを確認してください。
- 文字はSVGのパスに変換し、表示環境のフォントに依存させないでください。
- ローカルで開けるHTMLにし、表示時に外部フォントや外部画像を取得しないでください。
- 実際にブラウザーで表示して、余白、斜辺との接触、先後の向き、赤文字を目視確認してください。
- 利用した書体の出典とライセンス、再生成方法を保存してください。
- 既存の採用済みSVGと既存サンプルを保持し、新しい保存先に作成してください。

完了したら、HTMLの絶対パスへのリンク、各案の特徴、実際に確認した内容を日本語で報告してください。
```

希望する書体の指定例です。上のプロンプトの該当行を置き換えて使えます。

- 「筆で書いたような払いを持つ和風のアルファベットを3案。小さな盤上でもK・R・B・G・S・N・L・Pを見分けやすくしてください。」
- 「縦線と横線の強弱を抑えた、読みやすい明朝体を3案。細身・標準・太めで比較してください。」
- 「角に丸みがあり、落ち着いた印象のアルファベットを3案。既存の端正より柔らかな雰囲気にしてください。」

## 採用したサンプルをShogiBoardQへ組み込む依頼

`/clear`後には、サンプルの保存先と採用する案名を具体的に書いてください。次の `[ ]` 内を実際の値に置き換えます。

```text
/home/nakada/GitHub/ShogiBoardQ/docs/dev/piece-font-request-prompts.md を読み、
以下の採用済みサンプルをShogiBoardQの駒として組み込んでください。

サンプル保存先：[/home/nakada/GitHub/ShogiBoardQ/design/piece-font-new/]
採用する案名：[案名を列挙、または「このHTMLにある全3案」]
採用する配色：[木肌・白・墨の全て]

サンプルの字形・太さ・字幅・配置・配色を維持し、既存の駒に追加してください。
先手・後手それぞれ15種類、1セット30枚のSVGを用意してください。
3案×3配色を採用する場合は9セット、計270枚です。

このMarkdownの「組み込み時の参照先と確認事項」に従い、リソース登録、外観画面、
設定保存、翻訳、生成スクリプト、説明資料まで整えてください。

アプリをビルドし、全セットの通常駒・成駒・持駒・盤面反転・設定復元を検証してください。
サンプルと組み込み後の表示を実際に見比べてください。
完了したら、選択方法と検証結果を日本語で報告してください。
```

## 確定済みの文字とファイル名

ファイル名は `Sente_<名前>45.svg` と `Gote_<名前>45.svg` です。
各SVGの `viewBox` は `0 0 45 45` で、駒種ごとの大小と回転は標準SVGの変換を保持します。

| 駒 | ファイル名の `<名前>` | 文字 | 文字色 |
| --- | --- | --- | --- |
| 王将 | ou | K | 黒 |
| 玉将 | gyoku | K | 黒 |
| 飛車 | hi | R | 黒 |
| 角行 | kaku | B | 黒 |
| 金将 | kin | G | 黒 |
| 銀将 | gin | S | 黒 |
| 桂馬 | kei | N | 黒 |
| 香車 | kyou | L | 黒 |
| 歩兵 | fu | P | 黒 |
| 龍 | ryuu | R | 赤 |
| 馬 | uma | B | 赤 |
| 成銀 | narigin | S | 赤 |
| 成桂 | narikei | N | 赤 |
| 成香 | narikyou | L | 赤 |
| と金 | to | P | 赤 |

高さ・下余白を揃える基準は、駒種別の縮尺を適用する前の座標です。
画面上で全種類の文字高や下余白を同じピクセル数に揃えると、小さな歩などの文字が相対的に大きくなるため、文字と余白にも五角形と同じ縮尺を適用します。

新規セットには重複しないIDを付け、追加セットのリソースは `:/pieces/<ID>/` に登録します。
既存の設定値が別の駒や配色を指すことがないよう、既存IDとカタログの順序を保って追加します。
分類を増やす場合は、画面だけでなく `appearancePieceFilter()` と `setAppearancePieceFilter()` の保存範囲も確認します。

採用するSVGと再生成スクリプトはGit管理対象に置き、再生成が無視対象の `design/` に依存しないようにします。
現在の `generate_alphabet_pieces.py` は端正・凛・墨の既存9セットを出力するものです。新書体の生成では、既存セットの出力を変えずに拡張するか、新しいスクリプトを用意します。

`tr()`や翻訳対象の表示名を追加したら、`lupdate`で翻訳ファイルを更新し、日本語・英語・簡体字・繁体字の訳を用意します。
駒セット数や見本数を変えた場合は、関連テストの期待値と日本語・英語の利用ガイドも更新します。

アプリ変更後の基本確認コマンドです。

```bash
cmake --build build -j4
ctest --test-dir build --output-on-failure -R '^tst_(piece_images|board_image_renderer|translation_files|dialog_appearance)$'
```

GUIでは `pieceVariants:<新規ID>` で各セットを確認します。
新しいおすすめの組み合わせを追加した場合は `pieceCombinations` のテストデータも追加します。
既存の `pieceCombinations:alphabet` は端正・凛・墨を対象にしているため、新しいセットも検証されると仮定しないでください。

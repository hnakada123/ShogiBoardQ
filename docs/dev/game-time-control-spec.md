# 対局の時間設定と時計表示の動作仕様

更新日：2026年10月10日

## 対象と前提

「対局」ウィンドウから開始する、人間同士・人間対エンジン・エンジン同士の通常対局を対象とする。CSA通信対局の時間管理はサーバーの設定・裁定に従うため、本書の対象外とする（エンジンへの時間の送り方だけは「エンジンへの時間指定」に記す）。

本書は、2026年10月10日時点の仕様と実装を記述する。CSA通信対局の盤の時計も、本書の表示規則（「秒読みを設定した場合」の秒読みの表示を含む）に従う。

**時間無制限は、双方の持ち時間・秒読み・加算がすべて0秒の人間同士の対局に限る。** 片方だけ全項目0秒の設定と、エンジンが参加する時間無制限の対局は、対局ダイアログで開始させない（「対局開始時の時間設定の確認」を参照）。

連続対局の2局目以降と、中断した対局の「再開」は対局ダイアログを開かず、開始時に確認済みの時間設定をそのまま使う。連続対局で「1局ごとに手番を入れ替える」をオンにした場合は、エンジンと一緒に先後の時間設定も入れ替える（「連続対局で手番を入れ替える場合」を参照）。

## 設定項目

| 項目 | 意味 |
| --- | --- |
| 持ち時間（時間・分） | 対局者が対局を通して使用する基本の時間。秒へ換算して扱う。 |
| 秒読み（秒） | 基本の持ち時間を使い切った後、各手で使える時間。未使用分は次の手へ繰り越さない。 |
| 1手ごとの加算（秒） | 初手と、以後の各着手確定時に追加される時間。未使用分は残り時間として蓄積する。 |
| 後手／上手に異なる時間を設定 | オフなら左側の設定を双方に適用する。オンなら左右の設定をそれぞれに適用する。 |
| 時間切れを負けにする | オンなら使用可能時間を使い切った側を時間切れ負けとする。時間無制限の対局では時間切れ判定を行わない。 |

秒読みと加算は、両者に共通の方式として排他である。一方の秒読みに正の値を設定すると、両者の加算が0になる。一方の加算に正の値を設定すると、両者の秒読みが0になる。先手だけ秒読み、後手だけ加算、という併用はできない。

共通設定の場合、無効表示になっている右側の入力値は対局に使わない。

## 対局開始時の時間設定の確認

「対局開始」を押すと、対局に使う値（共通設定なら左側の値を双方に適用した値）で、次の表のとおり開始できるかを判定する。

対局者ごとの「時間あり」は、持ち時間が正であるか、または秒読み（加算方式では加算）が正であることをいう。秒読みのある対局では加算を使わないため、加算だけを設定した側は時間なしとして扱う。

| 条件 | 結果 |
| --- | --- |
| 双方とも時間あり | 開始する |
| 片方だけ時間あり | 開始しない |
| 双方とも時間なし・人間同士 | 時間無制限として開始する |
| 双方とも時間なし・エンジンが参加 | 開始しない |

開始しない場合は、題名「時間設定」の警告を表示し、設定を保存せずにダイアログを開いたままにする。警告の内容は次のとおり。

- **片方だけ時間あり：** 時間なしの側（先手／下手または後手／上手）を示し、片方の対局者だけを時間無制限にはできないと伝える。両方に時間を設定するよう求める。人間同士なら、時間無制限で対局する場合は両方とも0秒にする、という選択肢も示す。
- **エンジンが参加する時間無制限：** エンジンは使える時間を0秒と受け取り、ほとんど考えずに指してしまうと伝える。持ち時間・秒読み・加算のいずれかを設定するよう求める。

エンジンが参加する時間無制限を止めるのは、エンジンが `go btime 0 wtime 0 binc 0 winc 0` を「使える時間が0秒」と解釈するためである。2026年10月10日に YaneuraOu 9.10 で定跡を無効にして確かめたところ、この指定でも将棋所の形式の `go btime 0 wtime 0 byoyomi 0` でも、約0.1秒で `bestmove` を返した。

片方だけ時間ありの設定を止めるのは、そのまま開始すると対局全体が時間制限ありとして扱われ、全項目0秒の側の使用可能時間が0秒になるためである。「時間切れを負けにする」がオンなら、その側は最初の手番ですぐ時間切れになる。全項目0秒を対局者ごとの時間無制限として扱う仕様は採らない（時間切れ判定、累積表示、エンジンの思考予算を対局者ごとに切り替える必要があるため）。

初回起動時の時間設定は全項目0秒で、エンジンを登録していると後手の既定はエンジンになる。このため、そのまま「対局開始」を押すとエンジン参加の警告が出る。これは意図した動作で、既定値に時間を入れることはしない。人間同士の対局が黙って時間制限ありで始まるのを避けるため、利用者に警告を見て時間を設定してもらう。

## 時計表示の共通規則

- 盤の横の時計は、各対局者について `HH:MM:SS` 形式で表示する。時間無制限の対局では、先頭に「消費」を付ける。
- 計時するのは手番側だけ。相手の手番の間は、その対局者の時計を進めない。
- 時間制限ありの場合は残り時間を表示する。内部のミリ秒値を秒へ切り上げるため、残り7.2秒は `00:00:08` と表示する。
- 時間無制限の場合は、それぞれの累積消費時間を `消費 HH:MM:SS` の形で表示する（英語は `Used`、中国語は `已用`）。残り時間と見分けられるように「消費」を付ける。秒未満は切り捨てるため、累積7.2秒は `消費 00:00:07` と表示する。
- 表示する文字数が変わるため、時計の文字列を設定するたびに、ラベルに収まる文字サイズへ合わせ直す。
- 判定・集計はミリ秒で行い、表示値の丸めによって使用可能時間を増減させない。
- 手番側の時計は、時間が少なくなると文字色を変える（相手側の時計は通常色のまま）。色は外観ダイアログの「残り10秒以下の文字」「秒読み・残り5秒以下の文字」に従う。

| 対局 | 「残り10秒以下の文字」 | 「秒読み・残り5秒以下の文字」 |
| --- | --- | --- |
| 秒読みなし（持ち時間だけ・加算） | 残り10秒以下 | 残り5秒以下 |
| 秒読みあり | 秒読みに入る前の持ち時間が残り10秒以下 | 秒読み中（持ち時間0秒の秒読み対局を含む） |
| 時間無制限 | 使わない | 使わない |

## 基本の持ち時間だけを設定した場合

基本の持ち時間から、手番中の経過時間を減算する。着手しても時間は追加しない。

例：持ち時間5分、秒読み0秒、加算0秒なら `00:05:00` で開始する。初手を3秒で指すと残りは `00:04:57` となり、次の自分の手番はその残り時間から計時する。

## 秒読みを設定した場合

基本の持ち時間が残っている間は、それを減算する。使い切ると、同じ手の途中で秒読みに移行する。切替をまたいだ経過時間も消費する。

秒読みに入った後、期限内に指すと、その対局者の秒読み時間を設定値に戻す。未使用の秒読み時間は蓄積しない。消費時間が秒読みの設定値に達した時点で時間切れとなる（「◯秒未満で指す」の扱い）。

例：持ち時間0秒、秒読み5秒なら、各手の使用可能時間は5秒。3秒で指しても次の手は5秒となる。

持ち時間0秒の秒読み対局は、開始時から秒読みに入った状態で始める。各対局者の時計は秒読みの秒数（秒読み5秒なら `00:00:05`）を表示し、手番が来るとその秒数から数える。

持ち時間を使い切った後は、手番でない間も、次の手で使える秒読みの秒数を表示する（`00:00:00` にはしない）。時計に残り時間を設定し直すとき（`setPlayerTimes()`）、持ち時間が0の側は秒読みに入った状態にする。CSA通信対局はサーバーの残り時間で着手ごとに時計を合わせ直すため、この規則によってローカルの対局と同じ表示になる。

## 加算を設定した場合

開始時に、双方の基本の持ち時間へ初手分の加算時間を足す。以後は、その対局者が期限内に指した時点で次の手の分を加算する。手番が来たときに、もう一度加算することはない。

```text
開始時の残り時間 = 基本の持ち時間 + 加算時間
着手確定後の残り時間 = 着手前の残り時間 - 今回の消費時間 + 加算時間
```

| 設定・操作 | 残り時間 |
| --- | --- |
| 持ち時間0秒・加算10秒で開始 | 10秒 |
| 初手を3秒で指す | 10 − 3 + 10 = 17秒 |
| 次の自分の手を5秒で指す | 17 − 5 + 10 = 22秒 |
| 持ち時間5分・加算10秒で開始 | 5分10秒 |

相手が指したことによって、自分の残り時間が増えることはない。時間切れ後や終局後の処理で、加算によって時間切れを取り消すこともない。

## 時間無制限（双方が全項目0秒）の場合

双方の持ち時間・秒読み・加算がすべて0なら、時間無制限として扱う。対局ダイアログからこの設定で開始できるのは、人間同士の対局だけである。

- 双方の時計を `消費 00:00:00` から開始する。
- 自分の手番中は「確定済みの累積消費時間＋現在の手の考慮時間」を表示する。
- 着手確定時に、その手の消費時間を累積へ加える。表示上の二重加算はしない。
- 着手確定後の時計は、その対局者の棋譜欄の総消費時間と一致する。
- 「時間切れを負けにする」がオンでも、対局時計による時間切れ負けは発生しない。
- 時間切れ間近を示す時計の警告色は使用しない。

例：先手が3秒、後手が2秒、先手がさらに5秒考えて指した場合、先手の時計は `消費 00:00:08`、後手の時計は `消費 00:00:02` になる。両者を合計した10秒をそれぞれの時計に表示するものではない。

秒未満は内部で保持する。例えば、同じ対局者が1.7秒、0.7秒使った場合、総消費時間の表示は順に1秒、2秒となる。棋譜の各手の表示秒数は、切り捨てた総消費秒数の前回との差分から算出する。

## 先後で異なる時間を設定する場合

チェックをオンにすると、基本の持ち時間、秒読みの長さ、加算の長さを先後別々に設定できる。ただし、秒読みと加算の排他、および時間無制限の判定は両者に共通である。

双方とも時間ありである必要がある。例えば「先手は秒読み5秒、後手は全項目0秒」の設定では対局を開始せず、後手／上手に時間がないことを警告する（「対局開始時の時間設定の確認」を参照）。「先手は秒読み5秒、後手は時間無制限」という組み合わせには対応しない。

対局情報と棋譜の「持ち時間」には、先後の両方を記録する（「棋譜に記録する持ち時間」を参照）。

## 連続対局で手番を入れ替える場合

「1局ごとに手番を入れ替える」をオンにした連続対局では、次の局でエンジンの先後と一緒に、先後の時間設定（持ち時間・秒読み・加算）も入れ替える。時間設定はエンジンに付いていき、各エンジンは全局を同じ時間設定で指す。

例：1局目を「先手 エンジンA 持ち時間10分、後手 エンジンB 持ち時間5分」で始めると、2局目は「先手 エンジンB 持ち時間5分、後手 エンジンA 持ち時間10分」になる。

エンジンの思考設定（先読みの有無など）も、エンジンごとの設定に従う。2局目以降も、対局情報と棋譜には各局の対局者・開始日時・持ち時間を記録する。

## 棋譜に記録する持ち時間

対局情報の「持ち時間」と、KIF・KI2・JKF の対局情報には次の書式で記録する。

| 対局 | 書式 | 例 |
| --- | --- | --- |
| 持ち時間だけ（切れ負け） | `分:秒` | `10:00` |
| 秒読みあり | `分:秒+秒読み秒数` | `10:00+30` |
| 加算あり | `分:秒+加算秒数秒加算` | `05:00+10秒加算` |
| 時間無制限 | `無制限` | `無制限` |
| 先後で時間が違う | `先手 書式 / 後手 書式`（駒落ちは `下手`・`上手`） | `下手 01:00+2 / 上手 02:00+3` |

分は60を超えても時間へ繰り上げない（2時間は `120:00`）。CSA形式では V3.0 の `$TIME:持ち時間秒+秒読み秒+加算秒` で書き、先後で時間が違う対局は `$TIME+:` と `$TIME-:` に分ける（例：`$TIME+:60+2+0` と `$TIME-:120+3+0`）。持ち時間だけの対局は `$TIME:600+0+0` と書く（`$TIME_LIMIT:10:00` は CSA V2 の「時:分」として10時間と読まれるため使わない）。時間無制限の対局は `$TIME` を書かない。

駒落ちの対局では、柿木形式の KIF と同じく、対局情報の対局者を「先手」「後手」ではなく「下手」「上手」で記録する。KIF・KI2 の局面図の持駒・手番（`上手の持駒：`・`下手の持駒：`・`上手番`）と終局行（`まで30手で上手の勝ち`）も下手・上手で書く。読み込んだ棋譜の対局情報が「先手」「後手」のままなら、局面図と終局行もそれに合わせ、1つの棋譜で呼び方を混ぜない。読み込みは、どちらの呼び方の局面図も読む。CSA形式では下手を `N+`、上手を `N-` に書く。対局終了のダイアログ（`上手の時間切れ。下手の勝ちです。`）と入玉宣言の確認・結果のダイアログも、同じ判定（対局情報の見出し）で下手・上手と呼ぶ。

## 計時の開始・中断・終了

- 初手が人間なら、対局開始処理で計時を開始する。相手エンジンの初期化完了を待つために時計を止めることはしない。
- 初手がエンジンなら、エンジン初期化待ちの間は時計を停止し、準備完了後に計時・思考を開始する。エンジン同士では双方の初期化を待つ。
- 累積表示が0秒から1秒へ変わるのは、実際に約1秒を消費した後である。
- 中断中は時計を停止する。再開時には保存した残り時間・考慮時間・累積時間を復元し、初手の加算を再度行わない。
- 「待った」は、時計を取り消す自分の手を指し始めたときの状態（双方の残り時間・総消費時間・秒読みに入ったか）へ戻す。取り消した自分の手と相手の応手、応手の後に考えていた時間は返す。考慮時間は「待った」を押した時点から数え直す。
- 続けて「待った」を押すと、押すたびにさらに2手ずつ戻る。対局の開始局面まで戻ると、それ以上は局面も時計も変えない（時計はそのまま進む）。
- 終局時は時計を停止し、終局行に記録する消費時間を確定する。以後は秒読みのリセットや加算を行わない。

「待った」のために、時計は手番の開始状態を履歴に積む。対局の時間を設定したとき（`setPlayerTimes()`）に履歴を空にして開始状態を1つ積み、以後は着手を確定するたび（`applyByoyomiAndResetConsideration1/2()`）に、次の手番の開始状態として積む。`undo()` は末尾の2つを取り除き、新しい末尾の状態に戻す。履歴は中断・再開の保存にも含める。人間の考慮時間を測るタイマー（人間対エンジンは時計自身、人間同士はストラテジーのタイマー）も「待った」で掛け直す。

「時間切れを負けにする」がオフでも、有限の時間設定が時間無制限の表示へ変わるわけではない。残り時間は0で止まり、消費時間の記録は続く。加算方式で残り0になった後に指しても加算はしない。秒読み方式では、着手確定時に秒読みを再設定する。

## エンジンへの時間指定

エンジンには、各対局者の残り時間と、秒読みまたは先後の加算時間を伝える。

加算方式の `btime`/`wtime` は将棋所の USI 仕様に合わせ、今回（相手は次の手番）に加算される時間を含めない。`btime + binc`（後手は `wtime + winc`）が今回の手に使える時間になる。対局時計の残り時間は次に使う加算分を含むので、送信時に差し引く。

- 例：持ち時間5分・加算10秒の初手では、時計は双方とも5分10秒で、`go btime 299750 wtime 300000 binc 10000 winc 10000` を送る（手番側は下記の余裕250ミリ秒を引いた値）。
- 先読み（`go ponder`）を始める時点では、自分の着手による加算がまだ適用されていない。そのため自分の残り時間はそのまま送り、相手の残り時間からは次の加算分を差し引く。

実際に送信する手番側の予算からは、通信・探索停止の余裕として最大250ミリ秒を差し引く。このため、表示が10秒でも、送信値の合計が9750ミリ秒になる場合がある。対局時計の10秒が減らされたことを意味しない。

加算方式では、余裕を `btime` から引く。`btime` が足りないときは手番側の `binc` を減らし、`btime + binc` が実際に使える時間を超えないようにする。例えば、持ち時間0秒・加算10秒の初手では `go btime 0 wtime 0 binc 9750 winc 10000` を送る。

YaneuraOu の配布版（v9.01〜v9.40）は、`btime + byoyomi + binc` から `NetworkDelay2` を引いた時間を思考の上限とする。このため、この送り方で使える時間を正しく見積もる（ShogiHome も同じ形で送る）。

CSA通信対局でエンジンが指すときも同じ形で送る。CSA の残り時間は手番の開始時に加算済みなので、加算方式では自分の残り時間から加算分を差し引く。

「時間切れを負けにする」がオフの対局では、GUI 側のエンジン応答待ちに30分の安全上限を設ける。エンジンが永久に思考し続けることまでは保証しない。

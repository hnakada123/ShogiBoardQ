AI クライアント連携（MCP）

Claude・Cursor・VS Code・Gemini CLI・Codex CLI から ShogiBoardQ の機能を使う

Model Context Protocol stdio 棋譜変換・解析・詰将棋生成 アプリ操作

概要

ShogiBoardQ は Model Context Protocol（MCP）のサーバーを同梱しています

1 MCP とは

MCP は、AI クライアント（Claude Desktop、Claude Code、Cursor、VS Code の GitHub Copilot、Gemini CLI、Codex CLI など）が外部のツールを呼び出すための共通規格です。ShogiBoardQ の MCP サーバー（shogiboardq-mcp）を登録すると、「この棋譜を CSA に変換して」「この局面を 10 秒解析して」「3手詰を5問作って」のような依頼を AI クライアントに話しかけるだけで、クライアントが ShogiBoardQ の機能を呼び出します。

2 アプリを起動しなくても使える機能

次のツールは GUI を起動せずに動きます（内部では shogiboardq-cli を実行します）。

ツール内容
convert_kifu棋譜ファイル／文字列を KIF・KI2・CSA・JKF・USI・USEN・SFEN 列に変換
validate_sfenSFEN の妥当性、手番、持駒、王手の有無、合法手数
list_enginesShogiBoardQ に登録済みの USI エンジン
analyze_position / analysis_status / analysis_result登録エンジンによる局面解析（MultiPV 対応、ジョブ方式）
search_mate / mate_statusgo mate 対応エンジンによる詰み探索（ジョブ方式）
generate_tsume / tsume_generation_status / stop_tsume_generation詰将棋局面の自動生成（ジョブ方式）
verify_tsume余詰検査（唯一解 / 余詰あり / 不詰 / 手数違い / 判定不能）
render_board_imageSFEN から盤面の PNG 画像を作成

render_board_image の出力例：GUI と同じ駒画像・配色で描画され、最後の指し手を強調表示できる

3 起動中のアプリを操作する機能

ShogiBoardQ を --automation オプション付きで起動すると、次のツールで画面上の局面や棋譜を読み書きできます。

ツール内容
get_app_state状態（待機・対局中・解析中など）、現在手数、棋譜ファイル名、未保存の有無、開いているダイアログ
get_position / set_position現在局面の SFEN と手順の取得、局面の設定
load_kifu / save_kifu / get_kifu / goto_ply棋譜の読み込み・保存・取得（形式指定、手数範囲指定）・手数移動
list_actions / trigger_actionメニュー動作の一覧と実行（許可リスト方式）
capture_screenshotメインウィンドウまたはダイアログのスクリーンショットを PNG 保存
list_dialogs / close_dialog / get_widget_text開いているダイアログの一覧、閉じる、ラベル・入力欄・テーブル内容の取得

リソースとして、現在局面の SFEN（shogiboardq://position/current）、現在の棋譜の KIF テキスト（shogiboardq://kifu/current）、登録エンジン（shogiboardq://engines）も提供します。

準備

ビルド済みの ShogiBoardQ と Python の mcp パッケージが必要です

1 ShogiBoardQ をビルドする

MCP サーバーは build/ShogiBoardQ（GUI）と build/shogiboardq-cli（GUI 不要のコマンド）を使います。現時点では配布パッケージに shogiboardq-cli は含まれていないため、ソースからビルドしてください。手順は Linux・macOS・Windows のビルド手順を参照してください。

git clone --recurse-submodules https://github.com/hnakada123/ShogiBoardQ.git
cd ShogiBoardQ
cmake -B build -S . -G Ninja
cmake --build build
./build/shogiboardq-cli version      # {"ok":true,"version":"..."} が表示されれば OK
2 Python と mcp パッケージ

Python 3.10 以上と公式の mcp パッケージが必要です。リポジトリの mcp/ ディレクトリにサーバーがあります。

# mcp パッケージだけ入れる場合（サーバーは PYTHONPATH で参照）
pip install mcp

# サーバーごとインストールする場合
pip install -e mcp
3 USI エンジンの登録

解析・詰み探索・詰将棋生成・余詰検査は、ShogiBoardQ の「設定」→「エンジン設定」で登録した USI エンジンを名前で指定します。任意の実行ファイルパスは受け付けません。詰み探索・詰将棋生成・余詰検査には go mate に対応したエンジン（KomoringHeights など）を登録してください。

4 環境変数

クライアントの設定でサーバーに渡す環境変数です。最低限 SHOGIBOARDQ_EXECUTABLE を指定します。

変数意味
SHOGIBOARDQ_EXECUTABLEShogiBoardQ のパス。アプリ操作ツールで起動中のアプリが無いとき --automation 付きで起動します。同じディレクトリの shogiboardq-cli も自動で見つけます
SHOGIBOARDQ_CLIshogiboardq-cli のパス（別の場所に置いた場合）
SHOGIBOARDQ_ALLOWED_DIRS読み書きを許可するディレクトリ（Linux/macOS は : 区切り、Windows は ; 区切り）。既定はホームディレクトリ
SHOGIBOARDQ_OUTPUT_DIRスクリーンショットなどの既定の出力先。既定は一時ディレクトリ配下の shogiboardq-mcp
SHOGIBOARDQ_AUTOMATION_SOCKET自動化ソケットのパス（アプリ側の --automation-socket と共通）
SHOGIBOARDQ_QUIT_APP_ON_EXIT1 にすると、サーバーが起動したアプリをサーバー終了時に閉じます（既定は残す）
PYTHONPATHpip install -e mcp をしていない場合、リポジトリの mcp ディレクトリを指定します

クライアント設定

どのクライアントでも「python3 -m shogiboardq_mcp を stdio で起動し、環境変数を渡す」だけです

以下は Linux の例です。/path/to/ShogiBoardQ はリポジトリの場所に置き換えてください。Windows では python3 を python に、パスを C:\\Users\\...\\ShogiBoardQ\\build\\ShogiBoardQ.exe のように書き換えます。設定後はクライアントを再起動（または MCP サーバーを再読み込み）してください。

1 Claude Code

プロジェクト内で次のコマンドを実行します（--scope user を付けると全プロジェクトで有効）。-- より後ろがサーバーの起動コマンドです。

claude mcp add shogiboardq \
  --env SHOGIBOARDQ_EXECUTABLE=/path/to/ShogiBoardQ/build/ShogiBoardQ \
  --env PYTHONPATH=/path/to/ShogiBoardQ/mcp \
  -- python3 -m shogiboardq_mcp

claude mcp list      # 接続状態を確認
2 Claude Desktop

「設定」→「開発者」→「構成を編集」で開く claude_desktop_config.json（macOS: ~/Library/Application Support/Claude/、Windows: %APPDATA%\Claude\）に追記します。

{
  "mcpServers": {
    "shogiboardq": {
      "command": "python3",
      "args": ["-m", "shogiboardq_mcp"],
      "env": {
        "SHOGIBOARDQ_EXECUTABLE": "/path/to/ShogiBoardQ/build/ShogiBoardQ",
        "PYTHONPATH": "/path/to/ShogiBoardQ/mcp"
      }
    }
  }
}
3 Cursor

プロジェクトの .cursor/mcp.json（全プロジェクト共通なら ~/.cursor/mcp.json）に記述します。

{
  "mcpServers": {
    "shogiboardq": {
      "command": "python3",
      "args": ["-m", "shogiboardq_mcp"],
      "env": {
        "SHOGIBOARDQ_EXECUTABLE": "/path/to/ShogiBoardQ/build/ShogiBoardQ",
        "PYTHONPATH": "/path/to/ShogiBoardQ/mcp"
      }
    }
  }
}
4 VS Code（GitHub Copilot）

ワークスペースの .vscode/mcp.json に記述します。VS Code ではトップレベルのキーが servers です。ユーザー全体で使う場合はコマンドパレットの「MCP: Open User Configuration」から同じ形式で追加します。

{
  "servers": {
    "shogiboardq": {
      "type": "stdio",
      "command": "python3",
      "args": ["-m", "shogiboardq_mcp"],
      "env": {
        "SHOGIBOARDQ_EXECUTABLE": "/path/to/ShogiBoardQ/build/ShogiBoardQ",
        "PYTHONPATH": "/path/to/ShogiBoardQ/mcp"
      }
    }
  }
}
5 Gemini CLI

コマンドで登録するか、~/.gemini/settings.json（プロジェクトなら .gemini/settings.json）の mcpServers に記述します。

gemini mcp add -s user \

  shogiboardq python3 -m shogiboardq_mcp
{
  "mcpServers": {
    "shogiboardq": {
      "command": "python3",

        "SHOGIBOARDQ_EXECUTABLE": "/path/to/ShogiBoardQ/build/ShogiBoardQ",

}
6 Codex CLI

コマンドで登録するか、~/.codex/config.toml に記述します。

codex mcp add shogiboardq \
  --env SHOGIBOARDQ_EXECUTABLE=/path/to/ShogiBoardQ/build/ShogiBoardQ \

[mcp_servers.shogiboardq]

args = ["-m", "shogiboardq_mcp"]

[mcp_servers.shogiboardq.env]
SHOGIBOARDQ_EXECUTABLE = "/path/to/ShogiBoardQ/build/ShogiBoardQ"
PYTHONPATH = "/path/to/ShogiBoardQ/mcp"

使い方

自然言語で依頼すると、クライアントが適切なツールを選んで呼び出します

1 依頼の例
依頼呼ばれるツール
「~/kifu/game.kif を CSA 形式に変換して ~/kifu/game.csa に保存して」convert_kifu
「この SFEN は合法な局面？ 王手はかかっている？」validate_sfen
「YaneuraOu で初期局面から 7g7f 3c3d の局面を 10 秒、候補 3 手で解析して」list_engines → analyze_position → analysis_result
「この局面に詰みがあるか KomoringHeights で調べて」search_mate → mate_status
「3手詰を 5 問作って。攻め駒は 3 枚まで」generate_tsume → tsume_generation_status
「この 5 手詰に余詰がないか確認して」verify_tsume
「この局面を画像にして ~/Pictures/board.png に保存して」render_board_image
2 長い処理はジョブになる

解析・詰み探索・詰将棋生成は開始ツールがすぐにジョブ ID を返し、クライアントが状態ツール（analysis_status など）で進捗と結果を取得します。ツール呼び出しを約 60 秒で打ち切るクライアントでも、数分の解析や生成を扱えます。生成は stop_tsume_generation で途中終了でき、ジョブ一覧は list_jobs、取消は cancel_job です。

3 局面と手の表記

局面は SFEN（startpos は初期局面）、手は USI 形式（7g7f、駒打ちは P*5e）で受け渡します。結果には人が読める要約と、プログラムが扱いやすい構造化データ（structuredContent）の両方が含まれます。棋譜のテキストや読み筋は既定で先頭の一定量だけ返し、max_chars や max_pv_moves で調整できます。

アプリを操作する

--automation 付きで起動した ShogiBoardQ を AI クライアントから操作できます

1 自動化 API を有効にして起動する

自動化 API は既定で無効です。--automation を付けて起動すると、所有者だけがアクセスできるローカルソケットで操作を受け付け、標準出力に automation: listening on ... と表示します。SHOGIBOARDQ_EXECUTABLE を設定しておけば、アプリ操作ツールを最初に呼んだときに MCP サーバーが自動で起動します（起動済みなら接続します）。

./build/ShogiBoardQ --automation
# ソケットの場所を指定する場合
./build/ShogiBoardQ --automation --automation-socket /tmp/shogiboardq.sock
2 依頼の例
依頼呼ばれるツール
「今表示している局面を教えて」get_position
「~/kifu/game.kif を開いて 30 手目に移動して」load_kifu → goto_ply
「表示中の棋譜を KI2 で ~/kifu/out.ki2 に保存して」save_kifu
「棋譜解析ダイアログを開いて、内容を読み取ってスクリーンショットを撮って」trigger_action → list_dialogs → get_widget_text → capture_screenshot
「盤面を反転して」trigger_action（actionFlipBoard）

未保存の変更がある状態で棋譜を読み込んだり局面を設定したりする依頼は、discard_unsaved を明示しない限り拒否されます。メニュー動作は許可リスト方式で、終了・上書き保存・言語切替などは実行できません。実行できる動作は list_actions で確認できます。

安全性と制限

ローカル専用・既定で無効・明示的な許可が原則です

1 安全性
  • 自動化ソケットは所有者だけがアクセスでき、ネットワークには公開しません。--automation を付けたときだけ有効です
  • ファイルは絶対パスのみ受け付け、SHOGIBOARDQ_ALLOWED_DIRS（既定はホームディレクトリ）の外は拒否します。既存ファイルは overwrite の明示が無ければ上書きしません
  • エンジンは ShogiBoardQ に登録済みの名前だけを受け付けます
  • メニュー動作は許可リスト方式で、終了・上書き保存・言語切替・ドックレイアウトの保存は実行しません
  • クライアント側でも、ツールの実行前に確認が求められるのが通常です（クライアントの設定に従います）
2 制限事項
  • トランスポートは stdio のみです（Streamable HTTP は未対応）
  • CSA 通信対局、対局の開始や指し手の実行、評価値グラフ画像の取得は未対応です
  • Windows の名前付きパイプ接続は実装済みですが未検証です
  • 配布パッケージには shogiboardq-cli が含まれていないため、ソースからのビルドが必要です

設計の詳細（JSON-RPC メソッド一覧、ジョブの状態遷移、テスト）は開発者向け文書 docs/dev/mcp-server.md と mcp/README.md を参照してください。
